No 4/2-bit vector modes, DOT4/DOT2 operators, or quantization instruction state machine was found in these active core sources.

**Proposed SIMD implementation shape:** first freeze a collision-free instruction encoding table against this CORE-V decoder; the paper's historical RI5CY/PULP assembly names are not evidence of identical current encodings. Five explicit precisions (32/16/8/4/2) need at least three mode bits. Adding two explicit multiplier opcodes to the existing seven needs at least four opcode bits. An alternative is a separate dot precision signal and generic dot operation, but its ID/EX capture still needs a defined enable. Preserve existing integer MUL/MULH, complex dot, and 8/16-bit behavior. Add 8×4-bit and 16×2-bit products with explicit signed/unsigned lane extension and a correctly sized reduction tree, then define the architectural 32-bit accumulation/overflow behavior. Merely changing the decoder produces neither lane separation nor the extra MAC throughput.

## 4. Quantization needs a coordinated EX + LSU operation

**Observed interfaces:** EX combines ALU/MUL/LSU readiness in [ex_stage.sv](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_ex_stage.sv:474). Arithmetic write data is selected at [line 198](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_ex_stage.sv:198); normal LSU writeback is at [line 228](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_ex_stage.sv:228), and its destination/write enable are captured at [line 451](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_ex_stage.sv:451). The core connects EX/LSU at [core line 835](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_core.sv:835) and [line 885](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_core.sv:885).

LSU permits two outstanding transactions ([line 85](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_load_store_unit.sv:85)), forms addresses as A or A+B ([line 346](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_load_store_unit.sv:346)), derives `trans_valid` from `data_req_ex_i` ([line 381](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_load_store_unit.sv:381)), and counts accepted requests/responses ([line 425](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_load_store_unit.sv:425)). Its data metadata/writeback readiness assumes ordinary loads/stores ([line 391](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_load_store_unit.sv:391)). OBI responses have no ready/backpressure signal; they pass through when valid ([obi_interface.sv](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_obi_interface.sv:62)). Core external bus errors are currently tied to zero at [core line 896](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_core.sv:896).

**Proposed integration, pending exact PDF ISA contract:**

1. Decoder emits dedicated quantization controls and accurately marks input registers. Capture two signed int16 inputs, threshold base, output packing state, nibble/crumb precision, and final destination at instruction acceptance. Here `.n/.c` select nibble/crumb; they are not continuation modes.
2. Add an explicit FSM for threshold request, response capture, compare/address update, input interleave, and final commit. To reproduce paper throughput, design the two-input interleaving deliberately; a strictly sequential reference implementation may establish correctness first but should not be reported as the paper's interleaved implementation.
3. At first integration, drain ordinary LSU traffic before quantization and give this operation explicit memory ownership. Track each accepted request. Keeping `data_req_ex_i` high while EX stalls can issue duplicate requests; lowering EX-ready does not itself stop the LSU transaction generator. Hold address/byte-enable stable until grant and capture every response since OBI cannot backpressure it. If permitting two outstanding threshold reads, preserve response order and associate each response with the correct input/search level.
4. Route threshold data to quantization state instead of normal load GPR writeback. Only final packed output may write/forward to `rd`, exactly once. Qualify EX-ready, EX-valid, RF write enable, and performance retirement consistently; holding a ready signal alone is insufficient.
5. Preserve pending-load destination metadata, post-increment/misaligned logic, store behavior, and memory response accounting. Define interrupt/debug/flush/reset behavior during the multi-cycle instruction; do not leave stale memory responses to a later instruction.

Current dependency infrastructure is reusable: ID compares A/B/C sources with EX/WB destinations at [line 543](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_id_stage.sv:543), forwards three operands at [line 617](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_id_stage.sv:617), and controller handles load stalls/forwarding at [line 1340](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_controller.sv:1340) / [1396](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_controller.sv:1396). Existing multiplier multi-cycle handling specifically uses operand C as feedback storage ([ID line 1509](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_id_stage.sv:1509)); it should not be reused for quantization without an explicit design.

CSR is not an existing precision selector. The scoped extension does not automatically require a new CSR. Existing `mcycle`/`minstret` and one programmable HPM counter can measure kernels: events are defined at [CSR line 1327](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_cs_registers.sv:1327). Counters default inhibited after reset ([line 1529](E:/cv32e40p-master/cv32e40p-master/rtl/cv32e40p_cs_registers.sv:1529)); benchmark setup must explicitly enable them.

## 5. Proposed implementation/verification order

1. Freeze current external RTL/version and reproducible file list; configure CPU testbench and FF RF FPGA baseline. Establish existing RV32IMC + 8/16-bit PULP functional regression before changing precision logic.
2. Freeze instruction encodings, lane signedness, scalar replication, accumulator overflow, quantization equality/tie behavior, threshold-memory layout, nibble/crumb packing behavior, and illegal forms in an ISA table plus executable reference model.
3. Add DOT4/DOT2 first; verify scalar reference equivalence and original DOT8/DOT16/MUL/MULH regressions. Then extend required ALU operations and width-dependent pack/extract paths.
4. Add quantization FSM and LSU ownership. Verify compare-boundary values, min/max int16, both interleaved inputs, each precision, output packing, back-to-back operations, dependent consumers, x0, random grant/response latency, simultaneous grant+response, request stability, no duplicate/lost transactions, and single retirement/writeback.
5. Run instruction-level kernels using raw instruction encodings or a verified toolchain mapping. Count actual cycles/instructions and memory traffic under a documented memory-latency model; synthetic single-cycle arithmetic tests alone cannot establish NN kernel acceleration.
6. Compare baseline/extended synthesis and post-route timing with identical FPGA/RF/clock/memory settings. Report the existing 2026-10-20 utilization only as historical baseline evidence, not new results or ASIC-paper reproduction.

The external `example_tb/README.md` explicitly describes its testbench as sanity-level; full verification is separate. Reusing its memory/testbench infrastructure is a useful start, but extension-specific reference tests and transaction checks remain necessary.

## 6. Separate D:/fyp-xpulpnn prototype: reuse candidates and confirmed blockers

Parent investigation found a prior prototype at `D:/fyp-xpulpnn`. It is **not referenced by FYP.xpr** and is not the design whose successful synthesis is listed above. This audit only read it; no D-drive files were changed. Its code can provide implementation examples, not a verified drop-in extension.

Useful material exists: 3-bit vector modes and 4-bit multiplier opcode definitions ([D package](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/include/cv32e40p_pkg.sv:192)), sub-byte datapaths in `cv32e40p_alu.sv`/`cv32e40p_mult.sv`, operand replication, a quantization unit, instruction codelets, and a CPU testbench. However, it starts from a different PULP source revision (`PULP_XPULP` / `PULP_CLUSTER` parameters rather than active baseline `COREV_PULP` / `COREV_CLUSTER`), so wholesale file replacement would also replace unrelated core behavior.

### 6.1 Encoding is inconsistent with its document and changes baseline instructions

- [D package line 65](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/include/cv32e40p_pkg.sv:65) uses vector major opcode `OPCODE_VECOP=0x57`, while `0x7b` is `OPCODE_HWLOOP`. Its [ISA document line 31](D:/fyp-xpulpnn/docs/01_xpulpnn_isa_spec.md:31) instead claims all extensions use custom-3 `0x7b`. Active E-drive baseline uses `OPCODE_CUSTOM_3=0x7b`; D codelets ending in opcode `0x57` are not directly binary-compatible.
- [D decoder line 2412](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_decoder.sv:2412) reassigns `cv.extract` encoding to `pv.add` when `PULP_CLUSTER=0`; [line 2258](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_decoder.sv:2258) reassigns shuffle; [line 2549](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_decoder.sv:2549) reassigns complex multiply. Additional pack/min/max aliases are nearby. This is a deliberate feature tradeoff in source, not merely use of otherwise reserved encodings as [document section 6](D:/fyp-xpulpnn/docs/01_xpulpnn_isa_spec.md:93) claims.
- Quantization actually uses function bits `[31:26]=0x3f` at [D decoder line 2714](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_decoder.sv:2714), with `[13]` selecting crumb/nibble and `[12]` required zero. Its [document line 128](D:/fyp-xpulpnn/docs/01_xpulpnn_isa_spec.md:128) says function `0x2e` and incorrectly mentions bit 12 selecting n/c, contradicting the earlier document rule that bit 12 is zero.
- Signed nibble dot maximum in [document line 60](D:/fyp-xpulpnn/docs/01_xpulpnn_isa_spec.md:60) is wrong: eight `(-8)*(-8)` lanes yield **512**, not 392. Boundary tests must include the most negative signed operands.

### 6.2 Quantization arithmetic and threshold layout differ from the intended independent searches

The D unit explicitly states a simplified memory layout with one word `{threshold2,threshold1}` at each tree node ([header](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_quant.sv:13)). Its [document line 73](D:/fyp-xpulpnn/docs/01_xpulpnn_isa_spec.md:73) instead describes a second activation tree at a fixed offset. Result bits are two zero-extended codes at `[15:0]` and `[31:16]`, implemented at [quant line 227](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_quant.sv:227).

**Confirmed mathematical defect:** only one `node_q` exists. [Line 105](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_quant.sv:105) selects the right child if **either** activation is above threshold. Inputs can require opposite branches. For a 2-bit tree with root 0, left child -10, right child 10, and activations (-5,15), independent searches give bit codes `(01,11)` = `(1,3)`; the shared OR path yields `(00,11)` = `(0,3)`. This is a source-derived counterexample, not a simulator result. Two independent node/address states are required for general activation pairs.

### 6.3 Quantization handshake, restart, and pipeline control defects

| Blocker | Source evidence / implication |
|---|---|
| No request acceptance handshake | Quant interface [line 50](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_quant.sv:50) has busy/rvalid inputs but no grant/ready input. Root request pulses once in Q_IDLE ([line 131](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_quant.sv:131)); later requests pulse when previous rvalid arrives ([line 138](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_quant.sv:138)). A delayed grant can lose the request/address before acceptance. |
| Responses can be dropped | `consume` defaults zero and is only set in F states. U states ([line 147](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_quant.sv:147), [166](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_quant.sv:166), [178](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_quant.sv:178)) ignore a one-cycle response; the OBI channel cannot hold it until an F state. |
| Per-instruction search reset is ineffective | Q_IDLE sets `node_d/level_d/code*_d=0` at [line 125](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_quant.sv:125), but [sequential block line 208](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_quant.sv:208) never transfers these `_d` values into `_q`; those registers change only on reset or `consume`. A later instruction starts stale node/level/code state. |
| Back-to-back quantization cannot start a new search | Q_DONE leaves only when `enable_i` becomes zero ([line 190](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_quant.sv:190)). Consecutive qnt instructions can leave enable continuously high while EX accepts a new instruction, so the second operation sees old result/ready. An explicit accepted/start/retire protocol is needed. |
| Precision is stale | Decoder sets `alu_en=0` for qnt ([line 2715](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_decoder.sv:2715)). ID captures vector mode only under `alu_en` ([line 1525](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_id_stage.sv:1525)); the qnt branch captures A/B but no mode ([line 1552](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_id_stage.sv:1552)). EX computes `nibble_i` from that stale mode ([line 334](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_ex_stage.sv:334)). |
| Intermediate RF writes | EX [line 209](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_ex_stage.sv:209) propagates RF write enable without `qnt_ready`, while selecting qnt result at line 213. Old output can be forwarded/written during the busy operation; this requires final-commit gating. |
| Quant enable is not cleared on an EX bubble | [ID bubble path line 1603](D:/fyp-xpulpnn/src/cv32e40p-xpulpnn/rtl/cv32e40p_id_stage.sv:1603) clears normal controls but omits `qnt_en_ex_o`. Quant active/valid behavior after bubbles therefore needs correction together with the start/retire protocol. |

These facts invalidate the unit header's assertion that it is robust to memory latency and reproduces paper latency. The simplified layout and shared traversal are not a faithful independent two-input interleaving.

### 6.4 Existing D simulation is not a passing validation

[D xsim.log line 158](D:/fyp-xpulpnn/sim/xsim.log:158) reports `FAIL: 4800/4800 mismatches (23 cycles)` in a historical 2026-10-20 14:44 run. This audit did not rerun it, and that log alone does not isolate the cause of every mismatch. It directly rules out treating the existing artifact as evidence of a passing core regression. It also says nothing about the active C:/FYP project because the projects, sources, and instruction encodings differ.

Recommended reuse boundary: use D datapath ideas and test-generation scaffolding only after reviewing their independent reference model; port targeted changes to the frozen active baseline, resolve encoding compatibility explicitly, and redesign quantization control/search/LSU ownership before claiming correctness or performance.
